# Container security

The main API image runs as UID 10001 and Helm drops all capabilities, forbids privilege escalation, and uses a read-only root filesystem. Spark keeps its upstream user requirements; Airflow root/socket access exists only in the explicitly named development profile. No service is privileged.

Build-context exclusions cover `.git`, local environments, `.env`, datasets, reports, graph outputs and caches. The API Dockerfile no longer accepts MLflow/model URIs as build arguments or downloads artifacts during image construction. CI copies an explicitly selected model and publishes only an immutable commit tag.

Local host ports are loopback-only. Compose credentials are development placeholders and must be overridden outside an isolated workstation. Images are version-tagged but not digest-pinned; add digest update automation and SBOM/signature verification before production.

Trivy 0.76.1 was checksum-verified and executed. Dockerfile/IaC scanning initially reported five High missing-user findings; four images now declare explicit non-root users. Local MinIO retains root because changing its UID broke compatibility with the preserved named volume; it is loopback-only, and production must use managed/object-storage identity rather than this development image. The API runtime no longer installs curl and removes unused pip/setuptools after dependency installation. A freshly built image passed production smoke tests as UID 10001. Trivy still reports unfixed Debian base-package findings; the application does not invoke the affected archive, mount or package-management interfaces, but base images must be rebuilt and rescanned regularly. These findings are accepted for this local/publication milestone, not waived for production deployment.

The expanded Module II image scan is not accepted for merge: Airflow reports 34 Critical / 386 High occurrences and MinIO reports 6 Critical / 66 High occurrences. Their isolation reduces reachability but does not neutralize the Airflow Docker-socket consequence or vulnerable object-store binary. Flink was fully cleared by updating its shaded Jackson line. dbt and MinIO-init packaging tools were removed; dbt still needs a compatibility-line upgrade for `sqlparse`.
