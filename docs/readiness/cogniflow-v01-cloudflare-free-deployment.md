## Persistence and API behavior

Fresh initialization creates a **new empty D1 database**. Never import the Linux SQLite file. Only newly generated synthetic test records were used locally.

The schema stores owner-scoped sessions, append-only lifecycle/activity/effort events, completed windows, hashed browser sessions and synthetic estimate history. Events retain their UUIDs, idempotency keys, JSON representation and server-assigned ingestion time. Canonical Pydantic contracts preserve UTC requirements, field bounds, five-minute boundaries and label timing. Window UUIDs use the existing UUID5 namespace and timestamp representation. Session reads calculate confirmed active time with the existing semantics. Timeline queries paginate in SQL and sort by canonical event time and lifecycle sequence. Indexes cover session event order, window order, latest labels, estimate history and cookie expiry.

D1 does not provide the repository's SQLite connection transaction model. Each mutation validates a fresh snapshot, then sends a single atomic `DB.batch`: a version compare-and-swap, a named CHECK constraint asserting `changes()=1`, guard cleanup, windows/state updates and the event insert. A stale snapshot aborts the entire batch. Bounded retries re-read state; identical requests return their stored result, incompatible identities/transitions return 409. Global event/idempotency uniqueness also prevents duplicate identities across event types. Owner checks precede idempotent response retrieval, preventing another owner from replaying an event to obtain its data. Session snapshots and timeline page/count reads use batches.

## Browser authentication and security

Application authentication is deliberately single-owner. Generate a **new random 256-bit login credential**, store its SHA-256 digest as a Worker secret and save the credential in the owner's password manager. This is not a shared administrative API key or a human-chosen password; SHA-256 alone must not be used for low-entropy passwords. The Linux file-mounted API key is never read. The login credential is submitted once over HTTPS and is neither included in built assets nor retained in browser storage.

On login, the server creates a random opaque token, persists only its hash and returns `__Host-cogniflow` with Secure, HttpOnly, SameSite=Strict, Path=/ and an eight-hour expiry. Existing presented tokens are rotated on login; logout deletes the server record. Every private API checks token expiry and configured owner. Credential rotation should also revoke all existing browser sessions through the owner-scoped command below.

Mutations, including login/logout, require the exact configured Origin, an `X-CogniFlow-CSRF: 1` header, JSON content type and same-origin Fetch Metadata when supplied. There are no CORS grants. Request bodies are capped at 16 KiB. HTML/assets/API responses receive no-store, a CSP without inline/eval permissions, frame denial, nosniff, no-referrer, HSTS and a camera/microphone/geolocation denial policy. Only explicit asset paths are served. Health/readiness/docs/metrics and unrecognized API paths return 404. No public synthetic data endpoint or anonymous modification route exists.

Login has global and per-IP approximate limits of five/minute; private API traffic has an approximate owner limit of 120/minute. These use Cloudflare's binding and are per-location, eventually consistent protections, not strict global spending caps. Namespace IDs `26112601` and `26112602` need account conflict checks before publication. Attacks can still exhaust Free request quotas or temporarily lock out owner login. No paid WAF or rate-limit feature is assumed.

Cloudflare Access was considered: its Free offering targets small teams (under 50 users), but requires owner setup and policy/identity-provider decisions. Merely trusting an Access header would be unsafe; an Access implementation must verify signature, issuer, audience and expiry, including on alternate routes. The selected app login works independently on workers.dev without introducing account-wide Access changes. MFA and multi-user account enrollment are not implemented; use Access if those become requirements.

Executed security checks cover unauthorized reads/writes, cookie flags and JavaScript invisibility, cross-origin and missing-CSRF rejection, expiration/revocation/owner boundaries, rate-limit denial, malformed input, oversized bodies and sanitized database/quota failures. The local credential and its hash were checked absent from generated public assets and the dry-run bundle. Raw session bodies, tokens and credentials are not logged by application code; only exception class names are logged. Wrangler's local development logging is not evidence of production retention policy.
