The gateway preserves the G1B.2 timestamp/nonce/HMAC envelope, verifies the exact event ID, session, sequence, schema and SHA-256 payload digest, rejects non-synthetic source/subject data, caps body and request counts, and persists nonce/receipt records in test-only SQLite. It uses a bounded Kafka producer queue, `acks=all`, `enable.idempotence=true`, two retries and a 3-second delivery timeout. The Kafka key is `session_id`, so one session maps to one partition. A 200 response follows **both broker acknowledgment and local receipt commit**. A lost HTTP response after broker success is safe to retry by stable ID; it may still yield an extra Kafka record if the receipt commit fails after broker success. The consumer validates the same core identity/schema and partition key, stores event ID/digest durably, rejects conflicting ID reuse, and synchronously commits a Kafka offset only after SQLite processing commits. It bounds polls and exposes ID-level reconciliation plus separate record, attempt and logical-event counts.

## Real broker-backed failure matrix

The final integration script reported **14 passing scenario groups**. They cover the requested cases as follows; fault hooks are identified where used.

| Requested case | Final observation |
| --- | --- |
| Normal outbox → Kafka | D1 event/outbox committed; signed gateway request returned only after Kafka ack and receipt commit; consumer durably processed the event. |
| Duplicate HTTP delivery | Second signed request with a new nonce returned the same event ID/digest; one logical receipt. |
| Lost HTTP acknowledgment | Injected gateway 504 **after real Kafka ack and receipt commit**; dispatcher retried the same ID and reached acknowledged without a second gateway publication. |
| Kafka unavailable before publication | The task-owned broker was actually stopped; dispatcher marked the row retryable and did not acknowledge it. |
| Broker restart | The same test volume/topic survived the broker stop/start; retry then published and acknowledged the pending event. |
| Gateway restart | Gateway process restarted with the same temporary SQLite file; an identical request reused its durable receipt. |
| Dispatcher crash before acknowledgment | Injected crash-after-lease and crash-before-D1-mark paths; the latter had already received a real Kafka ack. |
| Lease expiration/recovery and stale ack | Expired D1 lease was reclaimed; stale holder's acknowledgment update returned false. |
| Concurrent dispatchers | Two simultaneous workerd dispatches against one D1 row yielded exactly one delivery. |
| Consumer crash before offset commit | Durable SQLite write was performed, then the test exited before Kafka offset commit; restart replayed safely. |
| Consumer restart/replay | Same group and SQLite ledger retained one logical row per ID; duplicate processing attempt was counted. |
| Duplicate Kafka records | Directly published an identical second Kafka record; consumer counted the extra record but retained one logical effect. |
| Conflicting event ID | Signed conflicting HTTP reuse returned 409; a directly published conflicting Kafka record raised a consumer error without committing its offset. |
| Per-session ordering | First same-session event was retried before the second could dispatch; gateway receipts placed both on the same partition in increasing offsets. |
| Dead letter | Injected terminal gateway rejection left one inspectable D1 `dead` row. |
| Reconciliation | Exact acknowledged outbox, gateway receipt and processed consumer ID sets matched; duplicate attempt IDs were listed separately. A unit test verified that a missing ID is detected. |
| Invalid HMAC, nonce replay, malformed body | Returned 401, 409 and 422 respectively without Kafka publication. Separate local tests rejected non-synthetic source/subject. |

Final counts: **10 D1 events/outbox rows** (9 acknowledged, 1 intentional dead letter); **9 gateway receipts and 9 gateway-published Kafka records**; **4 deduplicated HTTP attempts**; **2 additional direct Kafka records** (one identical duplicate, one conflicting ID); **10 durably inspected distinct Kafka offsets**, **11 consumer processing attempts**, **9 distinct logical consumer IDs** and **2 duplicate processing attempts**. The conflicting Kafka record was rejected and its offset intentionally left uncommitted. Reconciliation had no missing/unexpected ID between the 9 acknowledged outbox rows, 9 receipts and 9 processed IDs; it identified repeated gateway attempt IDs. The broker-backed test was rerun after receipt-commit and synthetic-only validation changes, then rerun again after ID-level reconciliation was added. Earlier intermediate failures were test-harness gaps and are not counted as final passes.

## Guarantee and next dependencies

This local path demonstrates **at-least-once delivery attempts** from retained D1 outbox rows under recoverable conditions, with **idempotent downstream materialization** by event ID. Producer idempotence only suppresses certain producer retries; it does not create a D1/Kafka distributed transaction or an end-to-end exactly-once guarantee. A Kafka ack followed by a failed receipt write can create duplicate Kafka records on replay; the consumer's durable ID/digest check is required. The single local broker, loopback plaintext HTTP, process-local gateway admission cap and SQLite ledgers do not qualify a secure public ingress or distributed HA.

Next independently testable work: design and locally verify an external HTTPS ingress with TLS identity, durable nonce/receipt storage, secret rotation, bounded timeouts and network policy; separately resolve the G1B.3 Cloudflare Free CPU evidence gap. Production D1 migration/backfill, scheduling, Kafka ACLs/replication, schema evolution and operational retention remain separate owner approval gates. No production deployment follows from G1B.4.
