# Data Card — Personal Cognitive Load Monitor

The pre-cloud focus-session extension defines `self_reported_effort` as an
integer 1–7 rating supplied by the user after a completed five-minute window.
The original rating is retained; LOW/MEDIUM/HIGH is derived compatibility
metadata. See [`focus-session/contracts.md`](focus-session/contracts.md). No
focus-session user dataset has been collected or approved by this contract-only
change. PR 5 adds a separate, opt-in local dataset builder documented in
[`focus-session/multimodal-experiments.md`](focus-session/multimodal-experiments.md);
no private output from that builder is committed.

## Data source

**100% synthetic.** No real users, no collected behavioral data, no third-party
dataset. Every row is generated by [`src/data_generator.py`](../src/data_generator.py)
via `random.randint`/`random.uniform` calls seeded for reproducibility.

There is no real-world data in the tracked training datasets. The separate PR 5
focus-session experiment path can read an explicitly authorized owner's local
SQLite aggregates, but no such export is committed or used by the legacy model.

## Generation method

For each of `n_samples` rows (default 500, see `params.yaml`):

1. `total_minutes` ~ `randint(240, 480)` (a synthetic "4–8 hour workday").
2. `focus_minutes` ~ `randint(0.3 * total_minutes, 0.9 * total_minutes)`.
3. `distraction_minutes = total_minutes - focus_minutes`.
4. `tasks_due` ~ `randint(0, 10)`.
5. `hours_to_deadline` ~ `uniform(0.5, 168.0)`.
6. `date` = `start_date + 12 hours * row_index`, serialized to `YYYY-MM-DD` — a
   split-order field, not a model feature. Two consecutive rows can share a date.

## Label generation — read this before trusting any accuracy number

The `cognitive_load_level` label is **not** an independent ground truth. It is
computed by calling the exact same deterministic scoring function the API
uses as its non-ML fallback:
[`preprocessing_api.service.calculate_cognitive_load`](../src/preprocessing_api/service.py).
That function combines focus ratio, distraction ratio, task count, and
deadline proximity into a weighted score, then thresholds it into
LOW/MEDIUM/HIGH.

**Consequence:** a model trained on this data is learning to approximate a
known, hand-written formula from a downsampled/noisy view of its own inputs
(the model sees raw fields plus two ratios; the label additionally depends on
weighted combinations of those same fields). High accuracy on held-out
synthetic data demonstrates the model can recover a deterministic function
from features that determine it — it is **not** evidence that the formula
itself measures real human cognitive load, and it is **not** external
validity. See [`model-card.md`](model-card.md) for the honest framing of what
the reported metrics do and do not show.

## Reproducibility

- Random seed: `data.seed` in `params.yaml` (default `42`).
- Start timestamp: `data.start_date` in `params.yaml` (currently
  `2025-01-01T00:00:00+00:00`).
- DVC locks the generator, seed, start timestamp, raw CSV, processed splits,
  joblib output, and metrics file. It does not bind an MLflow numeric version
  or registered skops digest to that lock.
- The current isolated review worktree does not have every locked output in its
  local DVC cache. A fresh two-run reproduction has therefore not been claimed
  by this documentation correction.

Reproduce:

```bash
uv run --extra dev dvc repro
```

## Fields

| Field | Type | Range | Used as model feature? |
|---|---|---|---|
| `date` | string (YYYY-MM-DD) | starts at `data.start_date`; advances every two rows | No — split ordering only |
| `focus_minutes` | int | ≥0 (generated 72–432) | Yes |
| `distraction_minutes` | int | ≥0 (generated 24–336) | Yes |
| `tasks_due` | int | 0–10 | Yes |
| `hours_to_deadline` | float | 0.5–168.0 | Yes |
| `cognitive_load_level` | string enum | LOW / MEDIUM / HIGH | Training label |

Two additional engineered features (`focus_ratio`, `distraction_ratio`) are
derived at training and serving time by
[`preprocessing_api/features.py`](../src/preprocessing_api/features.py) — the
single shared implementation used by both the training script and the
FastAPI service, so training and serving cannot silently drift apart on
feature order or formula.

## Class distribution (last local `dvc repro` run)

From `reports/metrics.json` (regenerate with `dvc repro` — do not treat this
snapshot as fixed forever):

```json
{"MEDIUM": 305, "LOW": 120, "HIGH": 75}
```

The current report's test partition contains 24 LOW, 60 MEDIUM, and 16 HIGH
rows. Classes are imbalanced; the selected random forest uses
`class_weight="balanced"`. The split is not stratified: rows are sorted by
`date`, then divided positionally at 80%. Because two rows can share a date, a
date group can cross the split boundary. The current pipeline does not check
group overlap because the synthetic rows contain no person or session identity.

## Known biases and limitations

- **No real individual differences.** The generator has no concept of a
  specific person, chronotype, task type, or interruption cost — everything
  is drawn independently and uniformly within fixed ranges.
- **No person or session structure.** Rows are generated independently and
  cannot demonstrate person-level generalization. The chronological positional
  split is not equivalent to an independently verified group split, and its
  absence of identifiers prevents a group-overlap assertion.
- **No demographic attributes exist**, so no fairness/bias claims across
  demographic groups can or should be made from this dataset.
- **Label circularity** (above) means this dataset cannot support a claim of
  predictive validity against real cognitive load — only that the model can
  reproduce a synthetic rule.

## Privacy

The legacy tracked training dataset contains no real users or personally
identifiable information. Separate opt-in focus-session collection paths now
exist, but their local/private records are not part of this dataset and are not
evidence for this classifier. See [`responsible-use.md`](responsible-use.md).

## DVC versioning

Tracked via `dvc.yaml` (`generate_data` → `train_model` → `drift_report`
stages) and locked in `dvc.lock`. `.dvc/config` currently points `storage` to
